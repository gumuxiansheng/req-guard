# 2026-09-13 req-guard 工作日志

## 代码已按《AI工具合规保证规范》落地（P0+P1 + 方案B/C + CI 自举）

### 新增模块（core/，仍零依赖）
- `auth.rs`：审批锁 `ensure_human(action)`，依次要求令牌(B)/AI_CTX(A) + 可选 OOB_ONLY(C)；供 review/resolve/bypass 在 core 层调用（CLI/TUI/GUI 同约束）。
- `token.rs`：方案B reviewer token，SHA-256 哈希存 `~/.config/req-guard/guard.cfg`，原文仅 `token issue` 打印一次、人类带外持有；Unix 设 0600。
- `digest.rs`：手写 SHA-256（FIPS 180-4，过官方测试向量），供审计摘要。

### gate.rs 关键变化
- `PRE_COMMIT_BLOCK` 改真 **fail-closed**（`if [ ! -f ... ]; then exit 1`）；回归测试锁定不得再用 `if [ -f ]` 静默跳过。
- `ToolProfile` 升级为各工具原生 schema：claude/codebuddy 用 settings.json+env 注入(REQ_GUARD_AI_CTX)，codex 用 apply_patch+deny 包装，cursor 用 preToolUse 小驼峰+deny 包装；`DENY_SH/PS1` 把 exit1 转 exit2（Codex/Cursor 把非0视为 fail-open）。
- `run_hook` 解释器按 `cfg!(windows)` 选，不再"ps1 存在即调 powershell"（修跨平台恒败 bug）。
- `enforce.ci` 默认 `true`；`install` 生成 `.gates/ci/req-guard-ci.yml` 样例；新增 `verify_install()` + `req-guard install --verify`（CI 自检 L1/L2 静默缺口）。
- 审计：`gate-audit.log`（本机）+ 入库 `ledger.md`（关键事件表）+ `DIGEST`（SHA-256，可比对防篡改）。

### cli/main 接线
- approve/reject/resolve/bypass 均经 core `ensure_human`；`--token`→REQ_GUARD_TOKEN、`--oob`/`oob <cmd>`→REQ_GUARD_OOB；新增 `token issue|status|revoke`、`audit-digest` 子命令。

### 对照此前绕过分析：已堵 / 仍存
- 已堵：pre-commit fail-open(H)、ci 默认关(F)、审计不入库(I)、L1 静默缺口(D)、claude/codebuddy 经 Shell 自批(A 经 AI_CTX)。
- 仍存（诚实披露）：默认未启用令牌→codex/cursor Shell 自批仍不受阻（需显式 `token issue` 启用 B）；A 可被 env -u 剥离；B 强度靠"令牌只人知"非文件隔离；C 的 OOB_ONLY 仅强制"声明"带外、env 可伪造，真隔离需独立渠道/签名；L1 对 Shell 写文件固有限制靠 L2/L3 兜底。

## 修复 GitHub CI（windows-latest）gate.rs 4 例假红：marker 平台后缀误判

**症状**：CI windows-latest `cargo test --workspace` → core `54 passed; 4 failed`：
`hook_json按工具渲染原生schema`、`install每工具写入各自原生位置`、`install_claude写入审批锁env段`、
`verify_install_检出各层缺口`。本机 Win11 原样复现。

**根因**（不止测试，Windows 上有两条真实缺陷）：
- `hook_json()` 按 `cfg!(windows)` 渲染**平台相关**脚本：Win→`powershell … req-guard-check.ps1`/`req-guard-deny.ps1`；
  POSIX→`sh … .sh`（e46c296 引入）。
- 但"配置是否已接入门禁"的 marker（`marker_of`）**写死 POSIX 文件名** `req-guard-check.sh`/`req-guard-deny.sh`。
- 后果①：Windows 上重跑 `install` 幂等检查失配 → 凭空冒出"配置已存在且不含门禁，请手工合并"提示；
  后果②：`install --verify` 假报 **L1 静默缺口**（Windows 上 CI gate self-check 会红）；
  后果③：跨平台互认失效——Win 装的仓（配置里 `.ps1`）在 Linux/macOS 验（或反之）同样假红。
- 测试另把 `.sh` 字面量写死，一并红。

**修法**（仅 `core/src/gate.rs`）：
- 新增 `hook_script_rel(use_deny) -> &'static str`：平台相关脚本路径**唯一真相**，`hook_json` 与测试断言共用。
- `marker_of()` 改返回平台中立**词干**（`req-guard-check`/`req-guard-deny`，由 REL 常量 derive）——
  `.sh`/`.ps1` 形态一律识别为已接入；`verify_install` 文案随之改为"缺 … 的 .sh / .ps1 任一形式"。
- 测试改走 `hook_script_rel` + 平台命令前缀断言；新增回归 `门禁识别跨平台_已装配置不因平台后缀误判`
  （`.sh`/`.ps1` 两种既有配置都要 verify 全绿 + 无合并提示）。

**验证**：修前 core `54 passed; 4 failed` → 修后 `cargo test -p req-guard-core` 59 passed、
`cargo test --workspace` 64 passed（core 59 + tui 5）、`cargo fmt --all --check` 干净、
`cargo clippy -p req-guard-core --all-targets -D warnings` 干净。
真机端到端（`target/release/req-guard.exe`）：`init` 后再 `install --tool claude` 无"请手工合并"提示；
`install --verify` 退出码 0；把配置换成 POSIX 形态（`sh … check.sh`）再 verify 仍 0；
marker 对照：旧 `.sh` marker 命中 0 次、新词干 marker 命中 1 次（正是旧逻辑假红的直接证据）。

**环境坑（本次踩到，代价大）**：C 盘 936G 已用 932G，`cargo clippy --workspace --all-targets` 跑到一半写满
（cargo `磁盘空间不足 os error 112`），随后 Bash 工具 `ENOSPC: mkdtemp …Temp\codebuddy-shell-payload-*` 起不来，
连 PowerShell 建文件/删文件都失败。真相：**有 rust-analyzer 进程（flycheck）持着已删文件的句柄**，
`cargo clean` 删了 4G 但空间不释放 → `Stop-Process` 掉 rust-analyzer/rustc/cargo 后空间立刻回来（3.9G）。
诊断手法：输出被吞时用 `exit <码>` 回传数值（`(Get-PSDrive C).Free/1MB` 等）逐项探。

**约定沉淀**：跨平台工具里"渲染出的命令"可平台相关，但"识别/判定用的 marker"必须平台无关（取词干不取后缀）；
平台分支只允许一处真相，测试断言必须走同一分支源，禁止写死 `.sh`/`.ps1`。
