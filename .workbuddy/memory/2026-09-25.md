## 修复 GitHub CI `gate-selfcheck` 报错（L3 fail-closed 断言写反）

**现象**：`gate self-check` job 在 `install --verify` 处中止，报
「✗ 未检测到任何 CI 编排文件（…）——L3 未落地」，共 1 项未通过。

**根因**（`set -euo pipefail` 放大了它）：脚本在 `req-guard init -p $P` 后直接断言
「刚 init 完应全绿」，但

- `init`（与 `install` 同一分支）**有意不替用户写 CI 编排**，只把样例落到 `.gates/ci/req-guard-ci.yml`
  （`core/src/gate.rs` 安装流程注释明示）；
- `.gates/req-guard.yaml` 模板 `enforce.ci: true` 是 fail-closed 默认 → `verify_ci` 找不到
  调用 `req-guard` 的编排就计入 problems（退出码 1）。

两者叠加 → 临时目录里必然红 → `set -e` 立刻终止，后续 8 步全没跑。

**修复**（提交 `0c0a173`，仅两个文件）：

- `.github/workflows/ci.yml`：改成**双向自举**——
  先 `if install --verify; then exit 1`（未接 CI 必红，验证 fail-closed 本体），
  再 `mkdir -p $P/.github/workflows` + `cp .gates/ci/req-guard-ci.yml` 过去，然后断言必绿。
- `templates/ci/req-guard-ci.yml`：使用说明补「不复制出去 = L3 未落地，verify 会红」，
  并写明样例生成在 `.gates/ci/`。

**验证**：本机无可用 POSIX shell（Bash 工具 shim 缺 coreutils、PowerShell 禁止嵌套 bash），
改用 Python 逐条镜像该脚本逻辑端到端跑，**15 项断言全 PASS**：
未接 CI rc=1（且文案含「未检测到任何 CI 编排文件」）/ 接入后 rc=0 / 空目录 `ids --check` rc=0 /
未建需求 `check` rc=1 / 三段批完 `check` rc=0 / 双 id `ids --check` rc=1 / 在用工具缺 hook `verify` rc=1。
GitHub 侧待推送后实跑确认。

**沉淀**：`gates-toolkit-ci` skill 新增「req-guard 门禁自举：install --verify 的 L3 fail-closed」一节。

## 2. 修 CI `ubuntu-latest` 静态检查（winit 平台编译错误）— 提交 `6144d31`

**现象**：`verify (ubuntu-latest)` 的「静态检查」红：
`error: The platform you're compiling for is not supported by winit`
（`winit-0.30.13/src/platform_impl/mod.rs:78` 的 `compile_error!`）。

**根因**：`cargo clippy --workspace --all-targets` 会把 `gui` 拉进 build graph，而
`gui/Cargo.toml` 用 `eframe = { default-features = false, features = ["wgpu"] }` ——
本机 registry 里 `eframe-0.36.2/Cargo.toml` 的
`default = [accesskit, default_fonts, links, wayland, web_screen_reader, wgpu, winit/default, x11]`，
关掉 default-features 的同时**关掉了 x11 / wayland / winit-default** → Linux 上 winit 没有平台后端。
`cargo test --workspace` 同理必红，一并修。
**注意**：这是 **feature 缺失**，不是「缺 X11/Wayland 系统库」——CI 里原有那条注释不准确，已改准。

**修法**：给 `verify` job 加 job 级 env，让 lint / test 与已有的
`if: runner.os != 'Linux'`（GUI 构建门控）对齐：

```yaml
GUI_EXCL: ${{ runner.os == 'Linux' && '--exclude req-guard-gui' || '' }}
# cargo clippy --workspace --all-targets ${{ env.GUI_EXCL }} -- -D warnings
# cargo test   --workspace ${{ env.GUI_EXCL }}
```

**验证**（本机 Windows，配 MSVC 14.44.35207 + Win Kits 10.0.22621.0 后）：
四条命令全 `exit 0` —— `clippy --exclude`（11.07s）、`clippy` 全量（含 gui）、
`test --exclude`、`test` 全量；test 各 95 + 8 用例通过、0 失败。

**本机坑**：不带 MSVC 环境时 `cargo clippy` 会在 proc-macro（strum_macros / derive_more-impl）
链接阶段报 `linker 'link.exe' not found`（proc-macro 要链接成 dll），与改动无关；
本机跑 cargo 前须把 `...\VC\Tools\MSVC\<ver>\bin\Hostx64\x64` 前置到 PATH，并设 `LIB` / `INCLUDE`
（MSVC `lib\x64` + Win Kits `Lib\10.0.22621.0\{um,ucrt}\x64`）。
