## 本轮踩的坑（都已修，值得复用）
1. **windows-msvc 默认动态链 CRT**：产物依赖 `VCRUNTIME140.dll`，用户机没有就起不来。
   → 构建加 `RUSTFLAGS="-C target-feature=+crt-static"`；验证方式是直接在二进制里搜该 DLL 名。
2. **执行位写不进归档**：Windows 上 `chmod` / `os.chmod` 对本地文件是空操作（改完仍 0666）。
   → 权限位改为在 `tarfile.add(filter=)` 的 `ti.mode` 与 `zipfile.ZipInfo.external_attr` 里显式写入；
   **目录必须保持 0755**（写 0644 会导致解压后进不去）。
3. **Python 落盘默认 CRLF**：`write_text()` 在 Windows 把 `\n` 翻成 `\r\n` →
   ① `.sh` 进 tar 后在 Linux 执行失败；② `SHA256SUMS.txt` 带 CR 让校验脚本读到 `路径\r`，
   `[ -f ]` 恒假 → **全部文件报 MISSING**（这次的"假红"根因）。→ 统一 `newline="\n"`，校验脚本再 `tr -d '\r'` 兜底。
4. **归档根目录名取错**：临时目录建在 `dist/.trash/_build-…` 下，`arcname=work.name` 把临时名打进了归档。
   → 用 `arcname=src.name` / `f"{src.name}/{rel}"`。
5. **环境的批量删除保护**：`rm -rf` 整个发布包目录（>50 文件）或累计删除超阈值会被拦，
   连 Python 的 `rmtree` / `unlink` 也拦（走回收站代理，失败即 FAIL_CLOSED）。
   → 组装流程改成**全程不删除**：旧快照 `mv` 进 `dist/.trash/`，裁剪平台目录用 rename，
   归档先写 `.tmp` 再 `os.replace`。这条让脚本能在带删除保护的环境无人值守跑完。
6. **Git Bash 的 `/c/...` 传给 Windows Python** 会拼成 `C:\c\...` → `can't open file`。
   → 统一用 `cygpath -w` 封装（`W()` 函数）转换后再传参。
7. **PowerShell 两个 API 事实**：`$psi.ArgumentList` 是 `Collection[string]`，**没有 `AddRange`**，要逐个 `Add`；
   stderr 也必须 `ReadToEnd()`，否则缓冲区满会卡死。原生命令不能写 `& git ... 2>$null | Out-Null`（会被当文档）。
8. **`-p/--path` 必须写在子命令之后**：`req-guard -p <dir> init` → 解析器把第一个 token 当命令，
   报"未知命令: -p" 且退出码 2。自检脚本第一版就栽在这（.sh 与 .ps1 都改过来了）。
9. **架构探测**：`$env:PROCESSOR_ARCHITECTURE` 在受限会话里为空 → install.ps1 误判"不支持的架构"。
   → 三级兜底（env → 进程/机器级 → `RuntimeInformation::OSArchitecture`）。
10. **本机 PowerShell 宿主里 git 完全无法执行**（`& git --version` 无输出、无退出码）。
    → 自检脚本对 git 做存在性探测并降级为"最小 .git 桩 + ⚠️ 明示"，不谎报也不误报失败。
11. Windows 侧 `grep -c $'\r'` 的写法会误报 CRLF（本次因此白排查一轮），判换行用 Python 数字节最可靠。
