## GitHub CI（windows-latest）两处失败修复

### 1. core 单测 4 红：hook 脚本名跨平台不一致（已提交 5d3fdb5）
- 现象：`hook_json按工具渲染原生schema` / `install每工具写入各自原生位置` /
  `install_claude写入审批锁env段` / `verify_install_检出各层缺口` 仅 Windows 红，
  断言写死 `.sh`，而 `hook_json` 在 Windows 渲染 `.ps1`。
- 根因（不止测试）：`marker_of()` 只认 `.sh` 全名 → Windows 上 `install` 幂等检查
  冒出"请手工合并"伪提示、`install --verify` 报不存在的 L1 缺口（跨平台假红）。
  反向也成立：Windows 装、Linux 验同样假红（工具配置随仓库入库）。
- 修复：
  - 新增 `hook_script_rel(use_deny)`（按 `cfg!(windows)` 选四支脚本），`hook_json` 与测试共用；
  - `marker_of` 改为**脚本名词干**（`req-guard-check` / `req-guard-deny`），平台中立；
  - 新增回归用例 `门禁识别跨平台_已装配置不因平台后缀误判`。
- 验证：本机 Windows 59+5 全绿（原 54+4 红）；`clippy --workspace --all-targets -D warnings` 零告警；
  真机端到端：二次 install 伪提示 0 条、POSIX 形态配置在 Windows 仍识别、真 L1 缺口仍检出（exit 1）。

### 2. verify_gate.py 在 Windows runner 崩编码（已提交 09ff72d）
- 现象：`UnicodeDecodeError: 'charmap' codec can't decode byte 0x8f`（readerthread）
  + `UnicodeEncodeError` on print 中文。
- 根因：Windows runner 默认 cp1252；`print` 编码中文、`subprocess(text=True)` 按 ANSI 解码脚本中文输出。
- 修复：脚本顶部 `sys.stdout/stderr.reconfigure(encoding="utf-8", errors="replace")`；
  全部 `subprocess.run` 追加 `encoding="utf-8", errors="replace"`；CI env 兜 `PYTHONIOENCODING: utf-8`；
  `shutil.which("sh")` 为空时给可操作提示。
- 本地负对照： `PYTHONIOENCODING=cp1252 python -c "print('结论: 全部通过')"` 复现同款
  UnicodeEncodeError；修好后 `PYTHONIOENCODING=cp1252 python scripts/verify_gate.py` 13 场景全 PASS。

### 环境备注

**对本仓（req-guard）有用的结论——落地 `request-review` 时必须一并改：**
1. **`REQ_GUARD_AI_CTX` 必须剥离（致命）**：AI 会话注入 → GUI 子进程继承 → 人工点击 approve 被
   `core::auth::ensure_human` 拒（exit 1，还不在方案码空间）。对策：通过交互校验后剥离（**仅 GUI 模式**，
   TUI/TTY 回退路径禁止剥离），写审计 `ai_ctx_stripped=1`；未过校验不剥离、回 4。
2. **退出码归一**：`cli/src/main.rs` 解析错恒 2、运行时错恒 1，与方案 §4（2=驳回、5=用法错）冲突。
   建议 `request-review`：用法错→5、环境/鉴权不允许→4、写盘失败→2（沿用 §9）、**禁返 1**；其他命令保持 1/2。
3. **`ui_mode::detect` 需严格模式**：现状 GUI 不可用会回退 TUI，且 `REQ_GUARD_UI=tui` 能改写显式 Gui 请求；
   `--ui` 下必须「GUI 不可用即 4、不回退、忽略环境覆盖」。
4. **令牌模式（方案B）弹窗无令牌输入位** → 人工点击必失败；要么弹窗加令牌框（忽略 AI 传入 `--token` 并记审计），
   要么令牌模式下禁用 `request-review` 回 4/5。

   pending REQ 拦下（gates-toolkit 侧风险，靠降序推进 + 提示缓解；方案 §1.3 禁止改判定逻辑）。
