# 2026-09-15 req-guard 可靠性复核（报告评审 + 改造点）

## 复核结论：既有分析报告的 5 条论断全部成立（已回代码逐条验证）
1. **P0-1 pre-commit 无执行位**：`gate.rs::append_pre_commit` 用 `fs::write` 落盘 → 0644。
   实测 git 自己打印 `hook was ignored because it's not set as executable`，提交成功；
   而 `install --verify` 仍报「全部就位」（只查内容不查可执行位）→ 假绿。全项目仅
   `token.rs:196` 有 `set_permissions`。
2. **P0-2 L1 自断流程**：HOOK_SH 第 0 段只保护 `*.comments.md`，其余路径一律走 2/3 段判定。
   实测模拟 AI Write `REQ-001.md` 正文 → exit 1，且文案误报「不得编写/修改源码」。
3. **P1 check 放行摘要失真**：`gate_check` Pass 分支硬编码 summary，`detail`(stdout+stderr) 算好却被丢弃
   → bypass 窗口内脚本的 `BYPASS-HIT` 警告不显示。
4. **P1 bypass 可匿名**：`main.rs` `resolve_identity().unwrap_or_else(|_| "unknown")`。
5. **P1 done 死状态**：`status.rs:93` 能解析 `done`，hook 也跳过 done，但 `Action` 枚举无归档命令，
   `recompute_head` 永不产出 done。

## 本报告新增（原报告未覆盖）
- **原报告 P0-2 修复方案有坑**：放行 `.gates/requirements/*.md` 会连带解锁同文件内的
  `GATE:HEAD`/`GATE:STEP` 状态行 → AI 直接改写 `status=approved` 自批，绕过 CLI 的 `ensure_human`
  （审批锁是命令层，管不到文件层）。正确解法是**状态行与正文分离**（正文可写、状态禁改）。
- **第 0 段 file_path 提取脆弱**：用 `sed` 正则抠 JSON，unicode 转义/伪装字段可绕过 → 现有
  "禁止改评论文件"保护也不牢。应把 stdin JSON 解析下沉到 Rust 子命令。
- **拦截文案不分流**：写 .gates 内文件也报「不得编写源码」，会诱导 AI 改用 Bash（加剧绕行）。

## 改造优先级（待实施）
R1 chmod+verify 执行位 → R2 状态/正文分离（含 Rust 解析 stdin）→ R3 Pass 透传 detail+bypassed
→ R4 bypass 身份校验下移 core → R5 归档命令 → R6 文案分流 → R7 三段连批（保留审计粒度）
→ R8 列表展示标题（替代中文 slug 改文件名，避免跨平台文件名编码风险）。

## 已实施：R1 + R3（2026-09-16 凌晨）
- **R1 钩子执行位**：新增 `ensure_executable` / `is_executable`（`#[cfg(unix)]` 双实现，
  Windows 侧 `is_executable` 恒 true 以免 CI 假红）。install 落盘 4 个脚本 + pre-commit 后 chmod 755；
  **关键**：`append_pre_commit` 的"已接入"提前返回分支也必须补 chmod，否则旧版仓库（0644）
  重跑 install 永远修不好 L2。`verify_install` 增补执行位检查（内容对 ≠ 生效）。
- **R3 放行明细**：`GateVerdict::Pass` 加 `detail` + `bypassed`；脚本（sh/ps1）在绕过命中时
  额外输出机器可读 `REQ_GUARD_BYPASS=1`（常量 `BYPASS_MARKER`，由单测锁定两端一致——
  脚本是 raw string 无法插值）。summary 在绕过时改为 ⚠️ 警告。
  CLI 放行时**仅在 bypassed 时**打印明细（保持正常放行输出不变）；TUI 区分文案；GUI 把 summary 插到首行。
- 验证：core 64 + tui 5 单测全绿，clippy `-D warnings` 与 `fmt --check` 零告警，
  verify_gate.py 13 场景全过；真机确认 pre-commit 0755 + 未审批 commit 被拦 + 0644 自愈。
- 踩坑：`cargo clippy -D warnings` 不被识别，必须 `cargo clippy -- --D warnings` 形式即
  `cargo clippy --workspace --all-targets -- -D warnings`。
- 既有测试 `verify_install_检出各层缺口` 因新检查多报一项 → 该用例手工写 pre-commit 后需同步 chmod 755。
