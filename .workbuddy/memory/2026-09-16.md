# 2026-09-16 req-guard：R2 第一步「Rust 解析 stdin JSON」

## 背景
拦截脚本第 0 段（证据保护：AI 禁改 `*.comments.md`）原先靠 `sed` 正则从 PreToolUse
payload 里抠 `file_path`。JSON 允许 Unicode 转义，`.gates\u002f…comments.md` 与明文
**完全等价**，正则匹配不到 → 静默放过。脚本是"唯一判定真相"，会同时污染 L1/L2。

## 实施
- 新增 `core/src/json.rs`：零依赖递归下降 JSON 解析器（`Value` 树 + `get/find_str`），
  支持全部转义、`\uXXXX` 与代理对、多字节 UTF-8；非法输入返回 None 不乱猜。
  入口 `file_path_of()`：先取 `tool_input.file_path`，取不到再深搜兜底（兼容各工具 payload 差异）。
- `gate::pretool_block_reason(root, payload)`：命中 `.comments.md` 则写审计并返回拦截原因；
  取不到路径返回 None（放行给后续门禁，不误伤）。
- 新增 CLI 内部命令 `req-guard hook-check`（读 stdin，拦截 exit 1）。
- HOOK_SH / HOOK_PS1 第 0 段改为：**优先** `req-guard hook-check`，二进制不在 PATH 时
  退回原正则（保底，不完备）；顺序仍先于绕过窗口。
- verify_gate.py 新增场景 14（转义路径改写评论文件，期望 exit 1），需 `target/debug/req-guard`
  在 PATH，未构建则 SKIP（不给原脚本加前置条件）。

## 验证
- core 71 + tui 5 单测全绿；clippy `-D warnings`、fmt 零告警；verify_gate.py 14/14。
- 真机对照（三段已批准、排除门禁干扰）：同一转义 payload，
  **有 req-guard 在 PATH → exit 1 拦截**；**不在 PATH（退回正则）→ exit 0 放行**，坐实老实现漏洞。

## 遗留
- req-guard 不在 PATH 时仍走可绕过的正则兜底（降级路径，非回归）。
  若要彻底：可在"二进制缺失 + payload 含 file_path 却解析不出"时 fail-closed 拦截，
  代价是受限环境下 AI 写操作会被全拦。待定。

## R2 主体完成：清单正文可写、状态行不可改
- 裁决从二档升级为三档：`PretoolVerdict::{Continue, Block, AllowDoc}`；
  `pretool_block_reason` 被 `pretool_verdict` 取代（CLI 同步）。
- **不变式**：`.gates/requirements/*.md` 允许 AI 用 Write 整篇写（放行标记
  `REQ_GUARD_ALLOW_DOC=1`，脚本见标记直接 exit 0，不再要求三段已批准——
  否则"AI 填三段正文"这步被自己拦死）；但 `GATE:HEAD/GATE:STEP` 行必须与磁盘
  **逐行一致**，不一致即拦（防自批，审批锁只管命令层管不到文件层）。
- **片段编辑（Edit/MultiEdit）一律禁**：只提交 old/new 片段无法与基线比对，
  把 old_string 写成 `status=pending` 就能骗过"内容含 GATE 标记"的粗判。
- 新建清单文件不得自带 GATE 行（审批状态是 approve 的职权）。
- 兜底分支（无二进制）**不**放行清单正文，保持 fail-closed。
- json.rs 新增 `content_of / new_string_of / old_string_of`（统一走 `field_str`：
  先 `tool_input.<key>` 再深搜）。
- 验证：core 72 + tui 5 全绿，verify_gate.py 16/16（新增 14 转义路径、
  15 清单正文放行、16 篡改状态行拦截），clippy/fmt 零告警。
- 坑：Rust raw string 里 `\\n` 是字面双反斜杠，JSON 解不出换行；测试里要写 `\n`。
