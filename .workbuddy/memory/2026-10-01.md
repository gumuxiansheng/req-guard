# 2026-10-01

## 排查：`--features full` 后没有独立的 tui/gui 二进制

结论：**设计如此，不是构建失败**。

- `cargo build -p req-guard --features full` 实际成功（Finished / 1.8s，eframe 已缓存），
  `cargo tree -p req-guard --features full` 能列出 `req-guard-gui` + `req-guard-tui`，
  `target/debug/deps/` 里有 `libeframe*.rlib` / `libegui*.rlib`，产物 `target/debug/req-guard`
  79MB、内含 egui 字符串 → feature 确实生效了。
- 但 `tui/`、`gui/` 的 Cargo.toml **都没有 `[[bin]]`，只有 `[lib]`** → 永远只出 `.rlib`，
  不可能产生可执行文件。`full` 的语义是"把两个 lib 链进唯一 bin `req-guard`"，
  所以 debug 目录下**永远只有一个 `req-guard`**。
- 名字里带 ui 的 `req-guard-ui-<target>[.exe]` **只存在于 release 打包层**：
  `scripts/build-release.sh` 变体 2 是 `cargo ... --features tui` 后 `cp` 改名到
  `dist/req-guard-ui-<target>`。它仍是一个 `req-guard` 二进制，只是拷了一份改名。
  交叉矩阵两个变体：默认 CLI、CLI+TUI；**没有 `--features gui` 变体**（GUI 不可交叉编译）。
- 本地启动界面就是同一个文件：`req-guard ui`（自动探测：桌面→GUI、SSH→TUI）、
  `ui --gui` / `ui --tui` 强制。无需另外准备二进制。
- 本机 shell 里 `cargo` 不在 PATH，需要 `export PATH="$HOME/.cargo/bin:$PATH"`。

## 新增 `scripts/build-release-native.sh`（本机 release，不交叉编译）

- 起因：`scripts/build-release.sh` 是 Debian 容器专用（apt-get 装 mingw/binutils、下载 Zig +
  cargo-zigbuild 来交叉链接 macOS），在 macOS 上第一步就 `apt-get` 卡死，本机没法用。
- 新脚本只编 `rustc -vV` 自报的 host 三元组（不写死，Apple Silicon 上不会链接出 x86_64），
  两个变体 + 宿主 strip + SHA256SUMS + `--version` 自证，产物名与 CI 矩阵同名
  （`dist/req-guard-<host>` / `dist/req-guard-ui-<host>`），可直接和其它平台产物同放 dist/。
  实测：默认变体 726K、TUI 变体 1.0M（release + strip），整轮 ~40s（含 ratatui 全量编译）。
- 踩坑：本机的 `sed` 是 **toybox 0.8.13**，BRE 里 `[[:space:]]` 配 `v\?` 会静默返回空串 →
  版本自证假失败。脚本里两处解析全部改用 `awk`（第一个版本来自根 Cargo.toml，第二个来自
  `req-guard --version`）。`build-release.sh` 里那套 `sed -n 's/.../\1/p'` 只在 CI 的 GNU sed
  下成立，已在新脚本头注释里点明为什么不用。
- 已在 `build-release.sh` 头部加警告：本机只想出一份二进制请改跑 `-native.sh`。
