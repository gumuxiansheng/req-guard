## 1. 目录结构

```
docs/
├── README.md                  ← 本索引（导航 + 状态 + 清理记录）
├── 需求/
│   └── 需求分析报告.md          立项需求基线：功能范围、命令规格、目录规范、验收口径
├── 设计/
│   ├── 技术方案.md              总体架构：模块划分、数据模型、拦截脚本、注入、退出码
│   ├── UI架构细化方案.md         TUI/GUI 双模架构细化（已落地）：workspace、feature、探测、布局键位
│   └── GUI跨平台方案选型.md      选型决策记录（ADR 性质）：egui 可行性、S0–S5 对比、构建矩阵
├── 规范/
│   └── AI工具合规保证规范.md     三层保证模型（L1/L2/L3）+ 审批锁 + 部署验收清单
└── 提案/
    └── AI协同审核GUI自动弹出技术方案.md   未实现的前瞻方案 + §10 落地路径（P0–P5）
```

**分类原则**

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `需求/` | 立项期的"要做什么"——功能范围、验收口径 | 实现细节 |
| `设计/` | "怎么做"——架构、数据模型、UI、选型决策 | 部署操作手册 |
| `规范/` | 必须遵守的约束与验收清单（改动即需回归） | 探索性讨论 |
| `提案/` | 尚未落地的前瞻方案（含落地路径） | 已实现功能的说明 |

## 5. 维护约定

1. **新文档一律放 `docs/` 对应分类目录**，不再往根目录堆 md；根目录只保留 `README.md`。
2. 文档引用别的文档时写**相对路径**（如 `../设计/技术方案.md`）或本索引可查到的文件名，避免移动后失链。
3. 引用代码位置写**文件名 + 符号名**，不写行号（行号必然腐坏，见 4.1）。
4. 门禁能力/保证边界变化时，须同步 `规范/AI工具合规保证规范.md` 第 2.2、4、6 章并回归其验收清单。
5. 验证数字（用例数 / 场景数）以**实跑为准**，文档只记录日期快照；
   `cargo test --workspace`、`python scripts/verify_gate.py`（当前 13 个固定场景 + 1 个需二进制在 PATH 的条件场景）。
