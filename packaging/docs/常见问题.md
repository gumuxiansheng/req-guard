# 常见问题与故障排查

> 结论先行：先跑 `req-guard install --verify`，它能一次定位 80% 的"装了但没生效"。

---

## 1. 速查表

| 现象 | 最可能的原因 | 处理 |
| --- | --- | --- |
| `req-guard: command not found` | 安装目录不在 PATH | 见 §2.1 |
| `install --verify` 报"脚本缺失执行位" | 复制/解压丢了执行位 | `chmod +x .gates/hooks/*.sh`（§2.2） |
| Windows 上 `check` 恒拦截且中文乱码 | 拦截脚本缺 UTF-8 BOM | `req-guard install` 重写脚本（§2.3） |
| `git commit` 没被拦 | pre-commit 未注入 / 被 `--no-verify` | §2.4 |
| 装了 hook，AI 仍能写文件 | 工具配置未生效或工具未重启 | §2.5 |
| 三段全批了还是拦截 | 有未 resolve 的阻塞评论 | `req-guard comments REQ-00N`（§2.6） |
| 审批被拒："AI 会话禁止审批" | 审批锁生效（**这是对的**） | 换人类终端审批（§2.7） |
| AI 发评论被拒 | AI 只能 `--reply` | §2.7 |
| 跳步审批被拒 | `strict_order: true` | 先批前一段（§2.8） |
| 误删 `.gates/` 后 commit 报错 | **fail-closed** 生效 | `req-guard init` 重建（§2.9） |
| GUI 打不开 / 闪退 | 无图形栈 | 自动回退 TUI，或用 `--tui`（§2.10） |
| CI 里 `check` 说找不到二进制 | 未下载/未 chmod | §3 |
| 控制台中文乱码（非脚本 BOM 问题） | 代码页 | `chcp 65001`（§2.11） |

## 2. 详解

### 2.1 命令找不到

```bash
which req-guard || echo "不在 PATH"
```

- Linux/macOS：`export PATH="$HOME/.local/bin:$PATH"`（装到 `/usr/local/bin` 则改对应路径），
  并写入 `~/.bashrc` / `~/.zshrc`。
- Windows：`%LOCALAPPDATA%\req-guard\bin` 是否在**用户 PATH** 中；重开终端后生效。
- **AI 工具里找不到**：工具的进程环境变量可能不含你的交互式 PATH。
  解决：用绝对路径配置 hook，或在工具配置里显式把安装目录写进 `env.PATH`。

> 找不到二进制时门禁是 **fail-closed**：不是放行，而是拒绝一切写操作。
> 所以"命令找不到"表现为"AI 什么都写不了"，别误判成门禁失效。

### 2.2 脚本没有执行位（Linux/macOS 高频）

```bash
ls -l .gates/hooks/
# -rw-r--r--  ← 这样 git 会**静默跳过**钩子，L2 完全失效
chmod +x .gates/hooks/*.sh
git add .gates/hooks && git commit -m "fix: 补拦截脚本执行位"
```

git 在 Unix 上对不可执行钩子是**静默跳过**的，不报错、不告警。
`req-guard install --verify` 会单独检查执行位（内容对 ≠ 生效）。

### 2.3 Windows 拦截脚本乱码 / 恒拦截

`.gates/hooks/req-guard-check.ps1` 必须是**带 UTF-8 BOM** 的 UTF-8；
否则 Windows PowerShell 5.1 按 ANSI 解析，中文报错变乱码并抛 `ParserError` → 恒拦截。

```bash
req-guard install      # 会重写脚本（自带 BOM）
req-guard check        # 确认恢复
```

手工确认：用十六进制查看器看文件头三个字节应为 `EF BB BF`。

### 2.4 git commit 没有被拦

```bash
ls -l .git/hooks/pre-commit          # 存在且有执行位？
req-guard install --verify           # 会明确指出缺什么
```

- 用了 `git commit --no-verify` → 这是**已知的人为绕过**，靠 L3（CI）兜底；
- 用的是 GUI 客户端（SourceTree / VS Code）→ 部分客户端不读 `pre-commit`，同样靠 L3；
- 仓库是 worktree / 子模块 → 钩子在 `.git` 实际所在目录，需确认路径。

**项目还不是 git 仓库**时也会报缺口：`req-guard init` 会提示"未检测到 .git，已跳过 pre-commit 注入"，
`install --verify` 因此报 pre-commit 缺失。这是**预期行为**（没有 git 就没有这一层），
先 `git init` 再跑一次 `req-guard install` 即可补上。

> 同理，`scripts/selfcheck.ps1` / `selfcheck.sh` 在检测不到可用 git 时会自动退化为
> "建一个最小 `.git` 桩"来验证**注入链路**本身是否通，并在输出里明确标注 ⚠️——
> 那一步只证明注入可用，不代表你的真实仓库已经接好 pre-commit。

### 2.5 AI 工具 hook 装了但仍能写

1. 配置写进去了吗：`.claude/settings.json`、`.codebuddy/settings.json` 等应有 req-guard 段；
2. **重启 AI 工具会话**（多数工具只在启动时读配置）；
3. 工具是否支持 `PreToolUse`（不支持的工具只能靠 L2/L3）；
4. 用 `req-guard install --verify` 看它是否把该工具登记为"在用且已注入"。
5. 注意 Codex / Cursor 走的是 `req-guard-deny.*`（退出码 2 表达拦截），不是 `check`。

### 2.6 三段全批却仍拦截

多半是**未 resolve 的阻塞评论**：

```bash
req-guard comments REQ-001          # 找 [阻塞] 且 [open] 的条目
req-guard resolve REQ-001 C001 --author 寇工
req-guard check
```

绕过（`bypass`）**不会**覆盖评论证据保护——这是刻意设计：证据问题必须先被审核人关闭。

### 2.7 AI 被拒（审批锁）

| 动作 | AI 能否执行 |
| --- | --- |
| 填写清单正文 | ✅ 可以（否则无解） |
| `comment --reply` | ✅ 可以 |
| 新开 `comment` | ❌ 拒绝 |
| `approve` / `reject` / `resolve` | ❌ 拒绝 |
| `bypass` | ❌ 拒绝 |

判定依据是环境变量 `REQ_GUARD_AI_CTX=1`（由 `init` 注入到 AI 工具配置）。
需要更强的保证请启用方案 B（审批令牌）或方案 C（带外审批），见用户手册 §3.10。

### 2.8 跳步审批被拒

`strict_order: true`（默认）要求按 分解 → 方案 → 测试计划 顺序批。
确需放开：编辑 `.gates/req-guard.yaml` 把 `strict_order` 改为 `false`（需走评审）。

### 2.9 误删 `.gates/` 或 hooks

表现：`git commit` 直接失败（**fail-closed**）。修复：

```bash
req-guard init              # 重建资产与脚本
req-guard install --verify
```

需求清单若也删了，只能从版本库恢复——所以 `.gates/requirements/` 必须入库。

### 2.10 GUI 打不开

- GUI 变体在 `full` 特性下**会自动回退 TUI**；单独 `gui` 变体失败时请改用 `req-guard ui --tui`；
- Linux 无预编译 GUI（需 X11/Wayland/GTK，本机 `cargo build --features gui`）；
- 远程桌面 / 无 GPU 环境可能 wgpu 初始化失败 → 用 TUI。

### 2.11 中文乱码

脚本内的乱码见 §2.3；**终端显示**乱码（Windows）执行：

```cmd
chcp 65001
```

并把终端字体换成支持中文的（如 Cascadia Mono / 新宋体）。

## 3. CI 相关

| 问题 | 处理 |
| --- | --- |
| `req-guard: not found` | 下载后 `chmod +x`，或用绝对路径 `./req-guard` |
| 选错平台二进制 | Linux runner 用 `linux-x86_64`（musl 静态，不挑发行版）；ARM runner 用 `linux-aarch64` |
| 只红不拦（照样能合并） | 分支保护里把该 job 设为**必需状态检查** |
| 想校验工具 hook 是否齐全 | 流水线加 `req-guard install --verify` |
| 审计日志要不要入库 | `gate-audit.log` 不入库（本机），但 `DIGEST` 建议入库供 PR 比对 |

---

## 4. 卸载与残留

```bash
bash scripts/uninstall.sh        # 或 uninstall.ps1
```

卸载只删二进制与 PATH 条目，**不会**动项目里的 `.gates/`（那是你的审核资产）。
要彻底撤掉某个项目的门禁：删 `.gates/`、还原 `.git/hooks/pre-commit`、
移除 AI 工具配置中的 req-guard 段。
