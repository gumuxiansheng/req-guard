# req-guard 安装指南

> 面向"拿到发布包、要把它装起来并接入项目/CI"的人。
> 命令逐条可复制执行；遇到异常先翻 [`常见问题.md`](常见问题.md)。

---

## 1. 前置条件

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10/11、任意 Linux 发行版（x86_64 / aarch64） | macOS 需从源码构建，见 §7 |
| 运行时依赖 | **无** | Windows 版静态链接 CRT（不要求 VC++ 运行库）；Linux 版 musl 静态链接（不要求 glibc 版本） |
| git | 建议 2.x | 仅 `pre-commit` 拦截层需要；不影响 CLI 与 CI 层 |
| 权限 | 安装到系统目录需管理员/root | 装到用户目录（`~/.local/bin`、`%LOCALAPPDATA%`）无需提权 |
| 磁盘 | CLI ≈ 2 MB / TUI ≈ 9 MB / GUI ≈ 15 MB 每个二进制 | — |

先确认该拿哪一个二进制：

```bash
uname -s        # Linux / Darwin / MINGW64_NT…
uname -m        # x86_64 / aarch64 / arm64
```

## 2. 选哪个变体

| 变体 | 文件名 | 能力 | 适用 |
| --- | --- | --- | --- |
| **CLI** | `req-guard` / `req-guard.exe` | 全部 16 个命令、文本输出 | **推荐默认**：CI、服务器、脚本化、绝大多数用户 |
| **TUI** | `req-guard-ui` | CLI + 终端管理台（`req-guard ui --tui`） | 只有终端的 SSH/服务器环境、喜欢键盘流 |
| **GUI** | `req-guard-gui.exe` | CLI + 桌面管理台（`req-guard ui`） | 本机开发、需要鼠标点选审核（**仅 Windows 提供**） |

> 三者**判定逻辑完全相同**（同一份 `core`），只是渲染层不同。
> 装 CLI 就能用所有功能；TUI/GUI 只是把审核动作图形化。
> 若不确定，装 **CLI**；需要界面再追加装 UI 变体即可，二者可共存（用不同文件名）。

---

## 3. 方式 A：一键脚本安装（推荐）

脚本会做四件事：识别平台架构 → 挑选对应二进制 → 复制到安装目录并赋执行位 → 校验 `-V` 版本是否匹配本包。

### 3.1 Linux / macOS / Windows Git Bash

```bash
bash scripts/install.sh                      # 装到 ~/.local/bin（默认，无需 root）
bash scripts/install.sh --dir /usr/local/bin # 系统级安装（需 sudo）
bash scripts/install.sh --variant ui         # 装 TUI 变体
bash scripts/install.sh --no-path            # 不碰 shell 配置文件
bash scripts/install.sh --init               # 装完顺手在当前项目 init 门禁
bash scripts/install.sh --help               # 全部参数
```

常用参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--dir <目录>` | `$HOME/.local/bin`（无权限时自动回退） | 安装目标目录 |
| `--variant <cli\|ui\|gui>` | `cli` | 要装的变体 |
| `--bin-name <名字>` | 随变体（`req-guard` / `req-guard-ui`） | 落盘后的文件名 |
| `--no-path` | 关闭 | 不往 `~/.bashrc` / `~/.zshrc` 写 PATH |
| `--init` | 关闭 | 安装后对当前目录执行 `req-guard init` |
| `--force` | 关闭 | 覆盖同名文件 |

装完若提示"目录不在 PATH"，二选一：

```bash
export PATH="$HOME/.local/bin:$PATH"                    # 当前会话
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc # 永久（zsh 换成 ~/.zshrc）
```

### 3.2 Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -AddPath
powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -Variant ui -InstallDir C:\tools\req-guard
powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -Init      # 顺手 init 当前项目
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-InstallDir <路径>` | `%LOCALAPPDATA%\req-guard\bin` | 安装目录 |
| `-Variant <cli\|ui\|gui>` | `cli` | 变体 |
| `-BinName <名字>` | 随变体（`req-guard.exe` / `req-guard-ui.exe` / `req-guard-gui.exe`） | 文件名 |
| `-AddPath` | 关闭 | 写入**用户级** PATH（不碰系统 PATH） |
| `-Init` | 关闭 | 安装后对当前目录执行 `req-guard init` |
| `-Force` | 关闭 | 覆盖同名文件 |

`-AddPath` 只改当前用户的环境变量，重启终端后 `req-guard` 全局可用；
若不想改 PATH，直接用完整路径调用：`%LOCALAPPDATA%\req-guard\bin\req-guard.exe`。

## 4. 方式 B：手工安装（无脚本 / 离线分发场景）

### Linux

```bash
# 1) 按架构挑文件（x86_64 或 aarch64）
install -m 0755 bin/linux-x86_64/req-guard /usr/local/bin/req-guard
# 2) 确认
req-guard -V
```

### Windows

```powershell
New-Item -ItemType Directory -Force -Path "$env:LOCALAPPDATA\req-guard\bin" | Out-Null
Copy-Item bin\windows-x86_64\req-guard.exe "$env:LOCALAPPDATA\req-guard\bin\req-guard.exe"
& "$env:LOCALAPPDATA\req-guard\bin\req-guard.exe" -V
```

把上述目录加进用户 PATH（`系统属性 → 环境变量`，或用脚本的 `-AddPath`）。

> **不要用解压后直接双击运行的方式"安装"**：门禁要被 git hook / AI 工具调用，
> 必须在 PATH 里能被解析到，否则拦截脚本会因找不到二进制而 **fail-closed**（拒绝一切写操作）。

## 5. 接入项目（第一次使用必做）

```bash
cd your-project
req-guard init
```

`init` 会写入（幂等，可重复执行）：

```
.gates/
├── req-guard.yaml                  门禁声明（enforce.* 开关）
├── requirements/                   需求清单（REQ-00N-*.md）
├── hooks/req-guard-check.{sh,ps1}  拦截脚本（AI 工具 PreToolUse 直连）
├── hooks/req-guard-deny.{sh,ps1}   deny 包装（Codex/Cursor 语义：exit 2）
├── ci/req-guard-ci.yml             L3 流水线样例
├── README.md                       给审核人的 30 秒说明
├── audit/gate-audit.log            审计日志（不入库）
└── .gitignore                      忽略 .bypass/ 与 audit/*.log
```

同时会：

- 为检测到的 AI 工具（claude / codebuddy / codex / cursor）注入**原生 hook 配置**；
- 追加/更新 `.git/hooks/pre-commit`（保留既有内容，追加 req-guard 段）；
- 为 Claude Code / CodeBuddy 注入 `REQ_GUARD_AI_CTX=1` 会话标记（**审批锁**：AI 无法自批）。

接入就位自检（CI 也用这条）：

```bash
req-guard install --verify      # 缺口 → 退出码 1，并打印缺什么
```

`--verify` 检查五类东西：核心资产、拦截脚本、脚本**执行位**、各 AI 工具 hook、pre-commit 注入。
任何一项缺失都会红——这是防止"看着装了、其实没生效"的关键一步。

### 5.1 三层拦截模型（装完心里要有数）

| 层 | 手段 | 强度 | 绕过难度 |
| --- | --- | --- | --- |
| L1 | AI 工具 `PreToolUse` hook | 提醒 + 阻止写文件 | 改配置即可绕（所以不算墙） |
| L2 | git `pre-commit` | 提交前校验，**fail-closed** | 需 `--no-verify`（有痕） |
| L3 | CI `req-guard check` + 分支保护 | 服务端强制 | 需仓库管理员权限 |

**只有 L2 + L3 是墙。** 单机用户可以 `--no-verify` 绕过 L2，因此 L3 必须配：见 §6。

## 6. CI 部署（L3 强制门禁）

做法：`templates/ci/req-guard-ci.yml` 复制到 `.github/workflows/`，再把该 job 设为**必需状态检查**并保护 main 分支。

```bash
cp templates/ci/req-guard-ci.yml .github/workflows/req-guard-ci.yml
```

流水线关键两步：

```yaml
- run: ./req-guard check             # 三段未全批 / 有未解决阻塞评论 → exit 1
- run: ./req-guard install --verify  # AI 工具 hook 或资产缺失 → exit 1
```

### 6.1 CI 上怎么拿到二进制

| 方式 | 适用 | 示例 |
| --- | --- | --- |
| 下载 Release 二进制（推荐） | 有固定版本 | `curl -fsSL -o req-guard <发布地址>/req-guard-x86_64-unknown-linux-musl && chmod +x req-guard` |
| 从源码构建 | 内网/离线 | `cargo install --path . --locked` 或 `cargo build --release` |
| 仓库内缓存 | 极简 | 把二进制随仓库提交（注意体积） |

Linux CI 建议直接用 **musl 静态版**：不挑发行版、不挑 glibc 版本，`ubuntu-latest` / alpine 容器都能跑。

### 6.2 GitLab CI / CNB

`templates/ci/req-guard-ci.yml.gitlab` 提供等价的 GitLab CI 版本；
CNB 可在 `.cnb.yml` 中同样调用 `req-guard check` 与 `req-guard install --verify`，语义一致。

### 6.3 分支保护（不可省）

GitHub：`Settings → Branches → Add rule` → 勾选 `Require status checks to pass` → 选中 `req-guard-gate`。
不设这条，L3 只是"红了但照样能合并"，等于没装。

## 7. 从源码构建（macOS / 未覆盖平台）

req-guard 的 CLI 与 TUI 变体是**纯 Rust、零 C 依赖**，一条命令即可：

```bash
git clone <仓库地址> && cd req-guard
cargo build --release                                   # 零 UI 依赖，秒级
cargo build -p req-guard --features tui  --release      # CLI + TUI
cargo build -p req-guard --features gui  --release      # CLI + GUI（需本机图形栈）
cargo build -p req-guard --features full --release      # 三合一，自动探测界面

./target/release/req-guard -V
cp target/release/req-guard ~/.local/bin/               # 然后回到 §5
```

要求：Rust **≥ 1.88.0**（ratatui 依赖下限）。GUI 额外需要本机图形栈：
Linux 需 X11/Wayland + GTK 开发库；macOS/Windows 原生即可。

Windows + Git Bash 构建注意：`/usr/bin/link`（GNU coreutils）会遮蔽 MSVC 的 `link.exe`，
需把 MSVC `bin/Hostx64/x64` 前置到 `PATH` 并设置 `LIB`。

## 8. 升级

发布包是一次性快照，升级即"装新版覆盖旧版"：

```bash
bash scripts/uninstall.sh            # 或 uninstall.ps1（可选，也可直接覆盖）
bash scripts/install.sh --force      # 新版包内执行
req-guard -V                         # 确认新版本
```

跨版本注意：`.gates/` 的**清单与状态格式向后兼容**；升级后建议跑一次
`req-guard install`（会按新版覆盖拦截脚本）与 `req-guard install --verify`。

---

## 9. 卸载

```bash
bash scripts/uninstall.sh            # Linux/macOS/Git Bash
powershell -File scripts/uninstall.ps1   # Windows
```

卸载只移除**二进制与 PATH 条目**，**不会**删除项目里的 `.gates/`（那是你的需求与审核资产）。
若确要撤掉某个项目的门禁：删除 `.gates/`、还原 `.git/hooks/pre-commit`、移除 AI 工具配置中的
req-guard hook 段。

## 10. 安装后验收清单

逐条执行，全绿才算装好：

| # | 命令 | 期望 |
| --- | --- | --- |
| 1 | `req-guard -V` | 输出 `req-guard {{VERSION}}` |
| 2 | `req-guard --help` | 出现 16 个命令列表 |
| 3 | `req-guard init`（在项目内） | 生成 `.gates/`，无报错 |
| 4 | `req-guard install --verify` | 退出码 0（有缺口会打印具体项并退出 1） |
| 5 | `req-guard create -t "冒烟"` | 输出 `REQ-001` |
| 6 | `req-guard check` | 退出码 **1**（尚未批准 → 拦截，这是对的） |
| 7 | 三段 approve 后再 `req-guard check` | 退出码 **0** |
| 8 | `bash scripts/selfcheck.sh` | 全部 PASS |

第 6 步看见"退出码 1"别慌——那正是门禁在起作用。一键跑完 5–7 步：

```bash
bash scripts/selfcheck.sh          # Windows：scripts\selfcheck.ps1
```
