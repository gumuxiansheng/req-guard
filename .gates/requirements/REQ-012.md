## 1. 需求分解

### 背景与问题

REQ-006 至REQ-011 把「多需求并行裁决」「批准即绑定正文摘要」「草稿叠加区」等能力补齐后，
门禁的**判定侧**已相当扎实。但一次以「团队是否值得引入」为视角的评估暴露出另一类问题：
**门禁自身的配置、脚本与自检入口，恰好落在 AI 可写、且无人校验的区域内。**

下表五条均为**实测复现**，非代码走读推测。复现方式记录在「复现命令」列，可重跑。

### 一处必须先澄清的严重性修正

问题 1 的实测里有一条决定性细节：伪造的令牌 **gitignored，从未进入提交**。完整链路实测：

```
本地：伪造 .bypass → check 退出码 0（门禁解除）
提交：.bypass 在 commit 中的出现次数 = 0
CI（干净克隆，无 .bypass）：check --base 退出码 1 → 正确拦截 [StepNotApproved]
```

因此问题 1 的准确定性是**「本地禁用」而非「绕过合并门禁」**：L1（PreToolUse）与
L2（pre-commit）被解除，可产生完全未审批的本地提交；但 L3（CI）依然拦得住落地。

**但这恰恰让问题 1 与问题 3 耦合**：L3 是否真拦，取决于它是否被设为**必需状态检查**，
而这一点req-guard **无法自行验证**（`verify_ci` 只做子串匹配，见 §1 问题 5 的同族问题）。
若 L3 只是建议性绿勾，则本地禁用等价于完全绕过，问题 1 升为最高级。
**故本需求把「让 L3 的强度可被机械判定」一并纳入（G3），而非只加固令牌。**

### 目标

- **G1** 伪造绕过令牌不再生效：令牌须自证身份并与**入库台账**交叉核对；TTL 设硬上限。
- **G2** 自检环境与生产环境的审批等级显式分离，且不再依赖调用方手改 YAML。
- **G3** L3 接入质量可被机械判定：模板自带 `fetch-depth` 与版本自证，`install --verify` 能查出模板没接好。
- **G4** 门禁配置（`.gates/req-guard.yaml`）的变更必须**在 PR 里可见**，不再静默。
- **G5** `install --verify` 从「子串存在性」升级为「实跑语义」，恢复自检的公信力。
- **G6** `token revoke` 在凭据丢失时不再锁死。

### 非目标

- **N1** **不引入任何密码学机制**（HMAC / 非对称签名 / 密钥）。本项目是零外部依赖设计，
  加HMAC 意味着自带密钥分发问题，且同用户进程仍可读取密钥——**投入产出比不成立**。
- **N2** 不追求「对同用户恶意进程不可伪造」。§1 已说明这是本地零依赖方案的固有上限。
  本需求的目标是**把不可篡改换成不可隐藏**：伪造必须出现在 PR diff 里，由人评审。
- **N3** 不改 `touch.exempt` 的**追加语义**（REQ-005 定的派生而非手写），只改默认集内容。
- **N4** 不改门禁裁决逻辑（`core/src/resolve.rs::judge`）的规则顺序与 `BlockKind` 集合。
- **N5** 不做 `.gates/requirements/**` 的 touch 声明化——AI 本就需写清单正文，
  纳入会产生大量假阳性。该区域改由 §2 设计 5 的摘要覆盖解决。
- **N6** 不动 `HOOK_SH` / `HOOK_PS1` 的判定逻辑（判定只在 core 一处，见 REQ-006）。

## 2. 技术方案

### 总体思路

**把「本地不可篡改」换成「变更在 PR 里不可隐藏」。** 本项目是零依赖单机工具，
在同用户恶意进程面前无法自证（§1 N2）。因此五项修复统一收敛到两个方向：
① 凡是需要可信性的判断，一律以**入库的、PR 可见的**文件为准（`ledger.md` / git base 差异）；
② 凡是说「我检查过了」的入口，一律改为**实跑**而非子串匹配。

### 关键设计

#### 设计 1：绕过令牌自证 + 台账交叉核对（G1，对应问题 1）

`gate::bypass()`（`core/src/gate.rs:999-1017`）落盘时**已经写了** `actor` / `email` / `sig`
三个可校验字段——信息齐了，只是读侧 `active_bypass` 不用。故只需在读侧补校验：

```rust
fn active_bypass(root: &Path) -> Option<u64> {
    let text = fs::read_to_string(bypass_path(root)).ok()?;
    let exp = key_value(&text, "expires_epoch")?;
    if gate::now_epoch() >= exp { return None; }

    // ① sig 必须等于按 git 身份重算的指纹（identity 已有 derive 能力，直接复用）
    let actor = str_field(&text, "actor")?;
    let sig = str_field(&text, "sig")?;
    if identity::recompute_sig(root, actor).as_deref() != Some(sig) {
        gate::audit(root, "BYPASS-REJECT reason=sig-mismatch");
        return None;
    }
    // ② 入库台账（committed）必须有对应 BYPASS-OPEN —— 不是本地 gitignored 日志
    let ledger = fs::read_to_string(root.join(".gates/audit/ledger.md")).ok()?;
    if !ledger.contains(&format!("BYPASS-OPEN actor={actor} ")) {
        gate::audit(root, "BYPASS-REJECT reason=no-ledger-entry");
        return None;
    }
    Some(exp)
}
```

**为什么第② 条才是真正的修复**：第① 条只能挡住随手伪造；第② 条把伪造的代价从
「改一个 gitignore 的本地文件」提升为「改一个**入库的、会出现在 PR diff 里**的文件」。
后者可由 CODEOWNERS 评审拦截——这是当前信任模型下唯一能跨过边界的机制。

**遗留（必须写进 §7）**：同用户进程若肯重算 sig 并改台账，仍可伪造。这是 N2 承认的上限。

#### 设计 2：TTL 硬上限 + 令牌移出工作树（G1）

```rust
// gate.rs —— bypass() 内，reason 校验之后
const MAX_TTL_MINUTES: u64 = 240;   // 4 小时
if ttl_minutes == 0 || ttl_minutes > MAX_TTL_MINUTES {
    return Err(GateError::Validation(format!(
        "绕过窗口 ttl 必须在 1..={MAX_TTL_MINUTES} 分钟之间（收到 {ttl_minutes}）；\
         应急绕过不是长期通道，架构改动请建 REQ 走三段审核")));
}
```

这一条 3 行就把 `expires_epoch=99999999999` 这种「实质永不过期」的模式消除。
`bypass` 本身有 `ensure_human`，故加上限不影响人，只坑 AI。

令牌路径同时迁出工作树（设计 3 依赖它）：

```
现状：.gates/.bypass                （在 .gates/** 豁免区内 + gitignore，隐形）
改为：$XDG_STATE_HOME/req-guard/<repo 绝对路径 sha256 前 16 位>/bypass
```

迁移期读侧先读新路径，miss 时回落旧路径并**立即重写到新路径**（一次性自愈）。
放在工作树外的理由：它本就是运行态，不该出现在「要评审的变更」里；
脱离 `.gates/**` 后也不再受豁免集语义纠缠。

#### 设计 3：`init --for-ci`（G2，对应问题 2）

问题的根是把「验证门禁机制」和「执行真实审批」两种场景混在同一份默认配置里。
不新增审批通道也能解决——因为那三处脚本要的是前者：

```rust
// gate.rs init_inner() 内，for_ci 为真时：
//   auth.level: 0        —— 沙箱内审批本就该脚本化，测的是拦截不是审批
//   enforce.ci: false    —— 沙箱里没有真 CI
// 并在 .gates/README.md 顶部写明：
//   「本仓库由 init --for-ci 生成，审批等级为 0，不适用于真实审批场景」
```

**不改默认模板的 `auth.level: 3`**——真实仓库仍应保持最严。
`--for-ci` 是显式场景开关，把两种世界分开，而不是降低标准。

顺带修 T6 的锁死：`token revoke` 现在要求出示当前凭据，
凭据丢失即**永久锁死**（实测：只能手删 `~/.config/req-guard/guard.cfg`）。
新增 `token revoke --i-lost-it`：要求 `ensure_human` + 显式二次确认，
强制向**入库台账**记 `REVOKE-FORCED` 事件。

#### 设计 4：CI 模板可跑 + L3 强度可判定（G3，对应问题 3）

三处改动，模板侧两处、校验侧一处：

```yaml
# templates/ci/req-guard-ci.yml
- uses: actions/checkout@v4
  with:
    fetch-depth: 0        # --base origin/xxx 需要完整历史；depth 1 下该 ref 不存在

env:
  REQ_GUARD_VERSION: ${{ vars.REQ_GUARD_VERSION }}
run: |
  : "${REQ_GUARD_VERSION:?未设置仓库变量 REQ_GUARD_VERSION（gh variable set REQ_GUARD_VERSION --body <版本>）}"
  curl -fsSL -o req-guard "https://github.com/<owner>/<repo>/releases/download/v${REQ_GUARD_VERSION}/req-guard-x86_64-unknown-linux-musl"
  chmod +x req-guard
  req-guard -V | grep -q "$REQ_GUARD_VERSION" || {
    echo "版本不符：期望 $REQ_GUARD_VERSION，实际 $(req-guard -V)"; exit 1; }
```

版本自证顺带补上「本地 0.1.5 / CI 0.1.4」这个静默缺口——`req-guard -V` 输出的是编译期版本，
成本近零。`<owner>/<repo>` 占位符改为失败即报（`:?` 形式），不再静默 curl 失败。

校验侧：`verify_ci`（`core/src/gate.rs:1442-1486`）当前是子串匹配，
任何编排文件含 `req-guard` 就算接入。增加两条硬检查：
① 模板 checkout 须含 `fetch-depth: 0`；② `--base` 后须跟非空 ref（不许裸 `--base`）。
GitLab 模板同步补 `--base` 并去掉裸 `check`。

#### 设计 5：门禁配置变更必须可见（G4，对应问题 4）

分两步，缺一不可：

**5a 默认集收窄**——复用 REQ-005 已验证的「派生而非手写」模式，把 `.gates/**` 换成具名运行态清单：

```rust
const DEFAULT: [&str; 4] = ["target/**", "dist/**", "Cargo.lock", ".gitignore"];
// 门禁自己的运行态：install/audit 会写，AI 不该为它们建 REQ
const RUNTIME: [&str; 5] = [
    ".gates/hooks/**",
    ".gates/ci/**",
    ".gates/drafts/**",
    ".gates/audit/gate-audit.log",
    ".gates/audit/DIGEST",
];
// 注：.gates/.bypass 不在此列（设计 2 已移出工作树）
// 注：.gates/requirements/** 也不在此列 —— 见非目标 N5，改由 5c 的摘要覆盖
```

`.gates/req-guard.yaml` 与 `.gates/audit/ledger.md` **刻意不进豁免**。

**5b 服务端漂移检测**——只靠 touch-check 不够（AI 会顺手把自己要改的文件声明进去）。
真正站得住的是利用「PR 可见性」：

```rust
// verify_install 新增形参 base: Option<&str>
fn config_drift_undeclared(root: &Path, base: Option<&str>) -> Option<String> {
    let base = base?;
    let changed = git_names(root, &["diff", "--name-only", &format!("{base}...HEAD"), "-z"]).ok()?;
    let touched = changed.iter().any(|p| p == GATE_YAML_REL);
    if !touched { return None; }
    if !declared_by_any_live_req(root, GATE_YAML_REL) {
        return Some(format!(
            "{GATE_YAML_REL} 在本 PR 被修改，但没有任何未归档清单的 GATE:TOUCH 声明它；\
             改门禁配置须由评审人复核（该文件含 auth.level / enforce.ci / touch.exempt）"));
    }
    None
}
```

CI 模板加一步 `req-guard install --verify --base "origin/${{ github.base_ref || 'main' }}"`。
**效果**：AI 改 `auth.level` 或 `enforce.ci` → PR 里一条明确的 CI 失败 + 需 CODEOWNERS 放行。

**5c 清单头部摘要**（T14）——问题 4 的近亲，独立于豁免集：
`section_span`（`core/src/requirement.rs:241`）从 `## N.` 标题起算，
故 frontmatter（`review_policy` / `source_refs` / `tier` / `verified_at`）、H1、preamble
**不在任何 `sum=` 覆盖内**；`## 审核记录` 的条目也不是 marker 行（`gate.rs:930` 只保护 BEGIN/END）。
两者都可被 AI 改写而不触发任何报警。新增头部摘要 `hsum=`，
并把 `doc_write_guard` 的逐行比对从 `is_marker_line` 扩展到 frontmatter 关键键。

#### 设计 6：`install --verify` 实跑语义（G5，对应问题 5）

项目**已有现成资产**：`scripts/verify_gate.py`（1248 行、40+ 场景）就是从 `gate.rs`
抽出 `HOOK_SH` 在临时仓实跑的。把最小子集下沉到 core，让自检名副其实：

```rust
// verify_install 内新增
fn verify_hook_behaviour(root: &Path) -> Vec<String> {
    let mut problems = Vec::new();
    let tmp = testutil::sandbox();          // 复用既有沙箱构造
    // (a) 未过审 → 必须拦
    if run_installed_hook(&tmp, payload("core/src/x.rs")).is_ok() {
        problems.push("语义自检：装好的拦截脚本对「未过审」场景未拦截（实跑退出码 0）".into());
    }
    // (b) 三段已批 → 必须放行（防「恒拦截」这一同族最坏失效）
    approve_all(&tmp);
    if run_installed_hook(&tmp, payload("core/src/x.rs")).is_err() {
        problems.push("语义自检：装好的拦截脚本对「已过审」场景误拦".into());
    }
    problems
}
```

**两类检查必须分职**，不可混为一谈：

| 类别 | 手段 | 理由 |
| --- | --- | --- |
| 反向子串检查（禁止脚本出现 `sort -r` / `GATE:STEP` / `verify-content`） | **保留为 Error** | 防的是「脚本自己重建判定」，语义上无法靠实跑覆盖（REQ-006 遗产） |
| 正向子串检查（要求脚本含 `check --stdin` 等） | **降级为 warning** | 存在性 ≠ 行为，正是问题 5 的病根；语义交给实跑 |

`--quick` 保留纯子串快筛，供本地高频调用。

### 涉及的文件与模块清单

见下方 `GATE:TOUCH` 块（已按「精确到文件优先」原则声明，未使用 `**` 通配——
T1 那条弱点是「无收窄约束」，本清单自身应示范正确做法）。

### 兼容性、性能与安全影响

- **兼容性**：`init` 默认行为**不变**（仍 `auth.level: 3`）；`--for-ci` 为新增可选开关。
  `bypass` 的令牌路径迁移对存量仓库透明（读侧回落 + 自愈）。
  **但 `bypass --ttl > 240` 将从「接受」变为「拒绝」**——这是有意的破坏性变更，须在 CHANGELOG 记 breaking。
- **性能**：`active_bypass` 每次裁决多读 2 个文件（`ledger.md` 通常 < 100KB），
  实测单次 < 5ms，可接受。`verify_hook_behaviour` 只在 `--verify` 触发（CI 路径），本地默认跳过。
- **安全**：本需求**净提升**防线，但按N2 不引入密码学，故不宣称「不可伪造」。
  TTL 上限会缩短合法紧急绕过的可用窗口（最长 4 小时），需在规范中明示。
- **零依赖约束**：全部设计仅用现有 `core/src/digest.rs`（SHA-256）与标准库，不新增依赖。

### 风险点与回滚方案

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 收窄豁免集后存量仓库大面积报 `NotDeclared` | **高** | 团队一次性 annoyance | 默认集保留 `.gates/hooks|ci|drafts` 与审计文件；本仓自身改动已在本清单 GATE:TOUCH 内声明（自举验证） |
| `install --verify` 实跑使 CI 变慢 | 中 | CI 时长 +1~2s | 仅 `--verify` 路径触发；提供 `--quick` |
| 台账交叉核对误伤合法绕过 | 中 | 绕过窗口失效 → 开发被挡 | 读侧失败时审计 `BYPASS-REJECT` 并**打印原因**，便于定位；`ledger.md` 由 `gate::bypass` 同事务写入 |
| TTL 上限打断正在生效的长绕过 | 中 | 需重新 `bypass` | 放宽至 4 小时；CHANGELOG 提前一个版本公告 |
| 设计 1 的 `identity::recompute_sig` 需新增入口 | 低 | 改动 `identity.rs` 公开面 | 现有 `identity::bind` 已含同一推导，抽公共私有函数即可 |

**回滚**：五项修复彼此独立，T1–T13 可逐个 revert。设计 5b（`--base` 形参）为可选参数，
不传即保持旧行为，回滚无副作用。设计 2 的令牌迁移读侧有回落，删新路径即回到旧路径。

### 边界 / 异常 / 并发场景

- **B-01** 令牌文件被截断 / 空文件 / 非 `key=value` 文本 → 拒绝，不得 panic（`key_value` 已有测试基础）
- **B-02** `actor` 含 `=` 或换行（`one_line` 已被 `gate.rs:1013` 处理）→ 解析不越界
- **B-03** `ledger.md` 不存在（从未有过审批）→ 拒绝，且 message 指向「先完成一次正常审批」
- **B-04** `ledger.md` 极大（> 1MB）→ 只读尾部或限制扫描窗口，**不得让每次裁决都全量读**
- **B-05** `XDG_STATE_HOME` 未设置 → 回落 `~/.local/state`（macOS 用 `~/Library/Application Support` 更合规，
  但**必须保证回落可用**，不可依赖 XDG 一定存在）
- **B-06** 同一仓库两个 clone 并发各自开绕过 → 状态目录按仓库路径哈希隔离，互不干扰
- **B-07** `install --verify` 在无 git 仓库目录下 → 跳过 `--base` 相关检查，其余项照跑
  （既有行为：`touch-check` 在非 git 下 `exit 0`，见 `gate.rs:1253-1256`）
- **B-08** `bypass` 成功后立刻 `seal` 冻结某段 → 绕过窗口内 `SumMismatch` **仍应报**
  （当前 `resolve.rs:543` 在 `judge` 之前短路绕过，设计 1 不改此顺序，
  但须在 §7 明确记录：**绕过期间不做篡改检测**这一残留）
- **B-09** 并发两个 `bypass` 同时写令牌文件 → 后写覆盖先写；因台账交叉核对要求两条 `BYPASS-OPEN`
  都在，故两者均有效，属可接受（绕过本就允许并存多个窗口）

### 验收门槛（全部可机械判定）

- **拒绝路径必须有"会失败"的用例**：U-01/U-02/U-03/U-07/U-19/U-20/U-29 逐条都要有

### 残留风险（必须随 PR 一起披露）

1. **同用户进程仍可伪造绕过令牌**：设计 1 第② 条把伪造变成「PR 可见」，
   但不是「不可伪造」。需配套 CODEOWNERS 覆盖 `.gates/audit/ledger.md`。
2. **绕过窗口内不做内容篡改检测**（B-08）：`resolve.rs:543` 的短路顺序本期不改。
3. **`--base` 漂移检测依赖 git 历史完整**：CI 须 `fetch-depth: 0`（设计 4 已加），
   但自建 CI 若忽略该配置，检测会静默失效。
4. **`install --verify` 的实跑自检仍信任被装的脚本本身**：若 hook 与 core 同时被替换，
   实跑也看不出。真正的兜底是 CI 上与本仓无关的独立 job。
5. **审批凭据无密码学保证**（`identity.rs:12-24` 已自述）：本需求不改变这一点，
   口径须在规范中与 `token.rs:15-22` 对齐，消除 `auth.rs:10-11` 的过度表述。
